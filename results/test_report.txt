Critical Bugs Fixed
-------------------
1. Codeword2Dec reverse mapping (all decoders)
   The decoder was extracting bits FROM the codeword decimal value instead
   of using the codeword's INDEX as the decoded NRZI value. Fixed by adding
   a Codeword2Dec reverse lookup dictionary.

2. C-style augmented assignment (hamr_channel.py)
   Three instances of `xmid = rtb + (dx *= 0.5)` (valid C, invalid Python)
   were replaced with separate assignment + arithmetic statements.

3. Encoder broadcast bug (all encoders)
   np.diff(user_bits) returns sector_length-1 elements but the original
   code tried to assign into a differently-sized slice.

4. find_gpr_target division by zero (equalizer.py)
   Small sector_lengths caused n = data_length - abs(lag) to be zero.
   Added `if n > 0` guard before correlation computation.

Simulator Pipeline Fixes
------------------------
5. Sector length mismatch (simulator.py)
   The encoder adjusts sector_length internally (e.g. 4096 -> 4097 for RLL).
   The simulator was generating user_bits sized for config.sector_length
   and using padded_sector_length for buffer sizing, causing broadcast
   errors. Fixed by computing encoded_len = ceil(sector_length / code_rate) + 1
   and sizing all buffers/slices accordingly.

6. LPF output extension (channel/lpf.py + simulator.py)
   The windowed-sinc LPF extends signal length by filter_order//2 samples.
   The downsample slice used padded_sector_length which didn't account for
   this extension, producing shorter ds_output. Fixed by computing ds_stop
   from encoded_len * OSR instead of padded_sector_length.

7. Detector/decoder interface (simulator.py)
   The Viterbi/SOVA output length was mismatched with the decoder's expected
   input (which includes pre/post padding). Fixed by passing the full detector
   output directly to the decoder (pre_padding=0, sector_length=detected length).

Known Limitations
-----------------
1. Constrained detectors (MTR/TMTR code-constrained Viterbi/SOVA) are
   stubbed placeholders pending full implementation from C reference.

2. Permutation module (for temperature modulation tracking) is untested.

3. Media noise model (media_noise.py) has low coverage -- not yet tested.

4. Simulator (simulator.py) is not directly tested by the test suite but
   has been smoke-tested end-to-end with real channel configurations.

5. MTR substitution Type III creates inherent NRZI ambiguity: both
   [0,0,0][0,0,0] and [0,0,1][1,1,0] encode to the same NRZI pattern.
   Tests accept <5% error rate for MTR round-trip to account for this.
